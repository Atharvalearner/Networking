Reverse Address Resolution Protocol (RARP) is a Network Layer protocol that allows a device to obtain its IP address when it already knows its own MAC address. It was primarily designed for diskless workstations that did not have local storage to save an IP configuration. During boot, the device broadcasts a RARP request containing its MAC address, asking for its IP address. A RARP server looks up the MAC address in its database and replies with the corresponding IP address. RARP is now obsolete because it has been replaced by DHCP, which provides not only an IP address but also subnet mask, default gateway, DNS server, lease time, and many other configuration parameters.


# Reverse ARP (RARP)
Suppose a very old diskless computer boots.
It knows only: MAC Address - AA:AA:AA:AA
It does not know: IP Address
So it asks: "I know my MAC address. Please tell me my IP address."
This is Reverse ARP (RARP): MAC  →  IP

# Example:
Computer boots: Knows: MAC - AA-AA-AA
It Doesn't know: IP
so It broadcasts: My MAC is AA-AA-AA
What is my IP? RARP Server replies:
Your IP is: 192.168.1.10

# Why don't we use RARP today?
Because DHCP replaced RARP.

Why?
RARP could only provide: IP Address
where DHCP provides much more: IP Address, Subnet Mask, Default Gateway, DNS Server, Lease Time, NTP Server, Many other options

So today, RARP is essentially obsolete/vanished.




$ Proxy ARP:
Proxy ARP is a networking technique where an intermediary device - a router answers Address Resolution Protocol (ARP) requests on behalf of another device. Instead of the original device answering with its MAC address, the proxy device intercepts the request and responds with its own MAC address

# Example:
```
PC A                  Router                 PC B
192.168.1.10          Proxy ARP             192.168.2.20

	Who has 192.168.2.20?
-------------------------->

		Router replies: "I do"
		(MAC = Router)
	<--------------------------

PC sends frame to Router
Router forwards it to PC B
```

Why use Proxy ARP?
Historically it was useful when:
1. Hosts were misconfigured
2. Subnetting changes were being introduced
3. Devices didn't support proper routing
Nowadays, it's used much less because proper routing is preferred
